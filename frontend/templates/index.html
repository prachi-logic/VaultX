VERIFIABLE CRYPTOGRAPHY

Military-Grade Security Architecture

VaultX relies on mathematically sound cryptographic algorithms with zero trust assumptions on the server.

🔒

AES-256-GCM

Authenticated Encryption with Associated Data (AEAD)

  • 256-Bit Keys: 1.15 × 1077 possible key combinations; resistant to brute-force and quantum Grover attacks.
  • Galois Mode: Provides both confidentiality and authenticated ciphertext integrity in a single pass.
  • Web Crypto API: Executes natively in browser C++ engines via hardware acceleration (AES-NI).
🎲

96-Bit Nonce & CSPRNG

Cryptographically Secure Random Initialization Vectors

  • 12-Byte Fresh IV: Generated for every single upload via window.crypto.getRandomValues.
  • No Nonce Reuse: Prevents Galois/Counter Mode key recovery attacks by guaranteeing unique IVs.
  • Isolated Storage: IV is transmitted alongside ciphertext, while the key remains strictly in browser memory.
🛡️

128-Bit GCM Authentication

Tamper-Proof Integrity Verification

  • Polyval / GHASH Tag: Any bit modification to the stored ciphertext causes decryption to throw an immediate cryptographic exception.
  • Zero Silent Corruption: Malicious tampering in transit or on disk is caught before any plaintext is extracted.
  • No Man-In-The-Middle: Recipients receive verifiable proof that the file is bit-for-bit identical to the sender's original.
🌐

RFC 3986 Hash Fragment

Client-Side Zero-Knowledge URL Isolation

  • Hash Isolation: W3C and IETF standards dictate that URL fragments (#key) are never sent in HTTP request lines.
  • Zero Server Knowledge: The Flask backend, Nginx reverse proxies, and SQLite database never observe the decryption key.
  • Local Ephemeral Lifecycle: Keys exist strictly in RAM during decryption and are garbage-collected upon tab closure.

How VaultX Works

Three straightforward steps from local file to zero-knowledge verified decryption.

You select any file up to 25 MB. Your browser's WebCrypto engine generates a 256-bit key and encrypts the file locally with an authenticated GCM tag.

2. Secure Share Link

Only unreadable ciphertext is sent to the vault. A unique secure sharing link is generated, embedding the secret key exclusively after the URL # hash fragment.

The recipient opens the link. Their browser extracts the key from the hash, pulls the ciphertext from the vault, and decrypts the original file locally in RAM.
